# LinkNote 方案与实验

## 目标与验收
打开普通文件夹；左树只显示文件夹与 `.md` / `.markdown`（大小写不敏感）；右侧打开即编辑；当前段落/结构块显示源码，其他内容排版；鼠标与键盘可用；不需要手动保存。

当前版本包含中文与 emoji、自动折行、跨块选择、复制粘贴、撤销重做、目录新建/重命名/移动/删除到废纸篓、文件快速查找、全文搜索、文内查找与替换、链接跳转（含 `[[维基链接]]`）、外部变化检测、冲突保护与差异查看、异常退出恢复、可配置快捷键。表格按整块源码编辑，并在显示层对齐列；图片在正文内预览，可回到源码修改引用，网络图片需用户允许后才加载。

## 文件操作与精简快捷键（2026-10-04）

文件管理集中到左栏：`a` 新建、`r` 重命名、`c` 复制绝对路径、`d` 移到废纸篓、`m` 移动。保留用户指定的 `Shift+D`，与 d 一样需二次确认；Shift+A 同样新建。默认撤掉 Ctrl+N、Ctrl+Shift+N、F2/F3、左栏 Delete 等重复入口。旧动作仍可在 keys.json / 设置快捷键页显式绑定，已有自定义配置继续生效；F1 帮助只显示已绑定动作。

查找入口为 Ctrl+P，Tab 在文件名与全文之间切换，撤掉 Ctrl+O；文内 Ctrl+F / Ctrl+G 保留。设置入口保留 Ctrl+, 和鼠标按钮，取消 F4。F5/F6 调栏宽改用分隔线拖动或外观设置；F8 图片重载与 F9 网络图片许可进入「图表与图片」设置。移动使用左栏 m，撤掉 F7。保留 F1 帮助、F10 图片查看、F12 / Shift+F12 链接导航，保障纯键盘可用；Ctrl+W 切焦点、Ctrl+B 侧栏、Ctrl+S 立即保存、Ctrl+R 处理冲突及常用编辑键保留。Command/Ctrl 是终端兼容入口，不为减少数量而删掉。

新建规则：无扩展名补 `.md`，已有 Markdown 扩展名保留，其他格式拒绝；末尾 `/` 创建目录，不支持一次输入多级路径。同名不覆盖。选中文件夹则在其中创建，选中笔记则在其父目录创建。新建框 56×4，标题显示位置，一行输入、一句 `.md 笔记 · / 文件夹` 提示，底边为 Enter/Esc。

单击左栏笔记会打开内容并保留左侧焦点；空白、标题和边框可聚焦。双击笔记、Enter 或点击正文进入编辑；目录双击只切换一次展开。焦点仅由边框强调，标题固定「笔记」。普通字母动作仅在左栏生效，正文和输入框继续输入文字。Ctrl+P 的 Tab 用于切换搜索；正文 Tab 用于缩进，不能全局拿来切焦点。

## 执行计划
1. 实验：确认 Markdown 源码区间、字素簇与屏幕宽度的映射；验证块展开后点击和光标仍指向原文。
2. 实现文档核心与混合布局：单一源码缓冲区，统一撤销，块级解析，屏幕到源码映射。
3. 实现持久化：500ms 防抖 / 2s 最长间隔、切换与退出保存、原子替换、外部修改保护与恢复草稿。
4. 实现双栏应用：文件树、鼠标、快捷键、创建/重命名、查找与错误提示。
5. 验证：行为与回归测试、真实终端输入与磁盘核验、发布构建；完成使用与验证文档。

## 设计选择
- 无参数启动固定打开 `~/Note`，与当前工作目录无关；默认目录不存在时创建，失败明确报错。`linknote open [路径]` 打开当前目录或指定文件/目录，保留原有显式路径入口。安装脚本提前创建默认目录，启动时补建；帮助和版本查询不创建目录。
- macOS 常用编辑动作同时绑定 Command 与 Ctrl；Unix 终端启动时 push Kitty `DISAMBIGUATE_ESCAPE_CODES`，退出时 pop，不做阻塞式键盘能力探测。Command/Super 保留在按键匹配中，未绑定的扩展修饰键不落入普通文本输入。搜索、替换、重命名等单行输入框复用 `Document`，各字段拥有光标、选区与独立撤销历史，绘制按字素簇水平滚动。终端原生快捷键可能优先于应用绑定；cmux 的菜单拦截属于终端侧适配边界。
- Ratatui + Crossterm 负责终端布局和事件，pulldown-cmark 提供块与内联语法的源码区间，unicode-segmentation / unicode-width 处理字素簇与单元格宽度。
- 完整应用参考：markdown-reader 的块级展开；edamame 的行内编辑；Shoin 的原子保存与冲突保护；ZenNotes 的输入后自动保存。
- 文本编辑与渲染共享一份文档。不会把每个块做成独立编辑器，因为跨块选区、粘贴、撤销应保持连续。
- `edtui` 可提供常规源码编辑，但它的标准视图与本工具混合排版所需的映射不一致；先验证自有轻量编辑核心，避免叠加两套光标和选区状态。
- 保留 Markdown 源文本，不通过 AST 重新生成文件。CRLF 文件加载时规范化为内部 LF，写回保持原 CRLF 风格。
- 文件监听先采用有节流的轮询：活动文件每秒检查，树定期刷新。普通笔记目录优先保证行为可预测。

## 实验记录
以下均已在本项目实现上执行，未安装参考应用冒充实测。

1. **块级渲染实验**：标题、含粗体与链接的中文段落、代码块组成样本。pulldown-cmark 给出的源码范围可以直接连接到当前缓冲区；只有光标所在块展开，其他块正常排版，原文保持不变。代码块进入后含围栏一起展开。结论：采用块级解析与自有屏幕映射，不需要让每个块拥有独立编辑器。
2. **Unicode 与折行实验**：中文、家庭 emoji `👨‍👩‍👧‍👦`、组合重音 `é`，在 4–19 列宽度遍历所有光标边界。屏幕位置再点击能回到原文位置，退格删除完整字素簇。发现并修复整行恰好占满时的行尾插入光标，需要额外可见插入单元格。
3. **跨块编辑实验**：跨标题与段落选择、一次粘贴替换、撤销和重做都作用于同一份源码。由此保留单一文档与统一历史；每个块单独嵌入编辑组件的路线不采用。
4. **持久化实验**：验证 CRLF 写回、未编辑的混合换行文件不重写、外部变更冲突、删除原文件、只读保存失败、排他锁、崩溃草稿与撤销回已保存状态时清理旧草稿。恢复记录与光标记录放应用数据目录，不污染笔记目录。
5. **真实 PTY 实验**：给实际进程输入按键、括号粘贴、SGR 鼠标事件和终端 Resize，并读取磁盘验证。修复重命名文件后的末尾分隔符问题；测试支持文件/文件夹新建、打开笔记期间父目录重命名、无手动保存、外部更新、保留冲突副本和 SIGKILL 恢复。测试在首屏就绪后发送输入，关键写回使用状态条件等待，避免把启动/磁盘调度时间当作产品失败。
6. **布局性能实验**：发布构建下，77,600 字节样本（800 组标题与中英混合段落）完整布局 30 次共 84.46ms，平均 2.82ms。这是本机测量，不承诺其他机器或 4 MiB 上限文件的相同性能。界面缓存当前布局，仅在文档、光标、选区或宽度变化时重算。
7. **大文件扩展实验（第二轮）**：同一样本放大到 1 MiB / 4 MiB 后，旧实现每次移动光标都整篇重新解析与排版（约 21ms / 91ms），`set_cursor` 从文首遍历字素（3ms / 10ms），撤销每组复制全文，恢复草稿把原文件存成 JSON 数字数组（4 MiB 笔记约 18.8 MiB，且输入时每 150ms 写一次）。据此改为：按块分段缓存排版、局部字素边界、按编辑记录的撤销、草稿只存指纹。改后 1 MiB 移动光标约 0.7ms、输入约 10ms；4 MiB 约 2.6ms / 41ms。输入时剩下的大头是整篇 Markdown 解析（4 MiB 约 25ms），暂未做增量解析。
8. **分段缓存的正确性**：增量排版必须与整篇重排逐行一致。属性测试随机生成 Markdown 片段并执行插入、删除、移动光标、选区、改宽度、改图片高度与撤销，每步对比两种结果；10 万组用例中发现并修正两类问题：同样的文本和范围可能被切成不同的块（列表吸收了后面的引用定义），以及同样的块文本因上下文不同而解析不同（引用定义之后的 `*` 是段落，标题之后则是空列表项）。因此复用条件同时比较块范围和块的事件签名。
9. **解析器边界**：随机测试还发现两处崩溃。一是旧实现按偏移量给块分配事件，表格缺单元格时空单元格事件落在下一个块的起点，紧跟列表时会让样式栈出栈为空而崩溃；改为按嵌套深度分组。二是 pulldown-cmark 0.13.4（当前最新版）开启 `ENABLE_WIKILINKS` 后，某些括号不配对的输入会在解析器内部 panic；因此不启用该选项，改为在纯文本片段中识别 `[[…]]`。
10. **终端探测吞键**：在 tmux（默认 `allow-passthrough off`）中，ratatui-image 的能力探测得不到回应，超时后其读线程仍阻塞在 stdin 上，会吞掉用户按下的第一个键（若第一下是粘贴，会丢掉开头）。库把超时报告为成功的后备结果，只能用耗时判断；超时后补发一次 `ESC[5n` 状态查询，让该线程读到回应后退出。tmux 实测首个按键恢复正常。

### 分段排版缓存

每次解析把顶层块分成“段”：段从两个块之间最后一个换行之后开始，因此每段都从一行的开头排起，单独排版的结果与整篇排版完全一致。`Layout::update` 接收上一次的布局：

- 文本没变（只移动光标或改选区）时不重新解析，只重排进入或离开源码状态的段；正在显示源码的段同时缓存一份完整渲染结果，光标离开时直接换回。
- 文本变了时，用前后公共前缀与后缀定位未受影响的段；后缀中的段整体平移源码偏移后复用。复用前比较段的块范围、块事件签名、文档级上下文（引用链接定义、脚注）和宽度，任何一项不同就重新排版。
- 光标插入格和图片占位行在段内加入并单独记录，复用时先去掉再按新状态加入。旧布局的行按顺序移动到新布局，不重新分配字形。

## 已知边界与后续方向

当前验收覆盖本地双栏笔记完整闭环。左右分隔线可拖动，外观设置每次调整两列，栏宽按目录保存在 session 中；小终端临时收窄不会改写用户偏好。表格按字素簇显示宽度分配列宽，支持对齐、边框与单元格换行，列太多时按记录纵向排版；编辑时仍展开整块源码。无序列表使用分级标记，有序列表显示连续有序祖先的编号路径，自动折行与源码软换行均保留正文缩进。整篇 Markdown 一次解析后分发事件，避免表格内引用链接丢失文档上下文。

侧栏标题右侧提供「<」，收起后在正文标题左侧保留「>」，正文占满原双栏区域。按钮与可配置的 Ctrl+B 共用动作，保留栏宽、目录状态、当前笔记和选区；收起时焦点转到编辑器。不足 64 列时按实际可见状态切换，展开转到文件树，收起回到正文。按钮只占一个字符，不带底色或额外留白，也不占正文行；模态窗口阻止背景点击，终端过小时清除旧点击区域。

表格阅读与源码编辑均保留外框和行间横线，单元格的视觉续行保持在同一格内；进入源码后采用虚拟空白对齐各列，实际源码字素只出现一次，光标优先定位真实字素，避免被虚拟空白吸走。装饰横线有独立标记，上下移动时跳过；横线点击只定位源码，不产生文字。原 Markdown 空格和管道符不重写。

兼容中文标点加粗只处理连续普通文本事件，不解释代码、HTML 和转义标记；活跃块仍可直接编辑原符号。按用户最新偏好，粗体使用亮暖白色 `#F2EFE2` 并保留 BOLD 属性，使中文粗体字形不明显的终端也能区分重点。文件标题仅显示 basename。

图片使用 ratatui-image 的 SlicedProtocol 支持裁切滚动，通过两个并发后台任务加载和编码。布局为图片预留行，画布点击映射回图片引用；活跃图片所在块展开源码。网络图片默认处于“待许可”状态，不发出任何请求，设置按笔记许可并记入 session。限额和格式见 [usage.md](usage.md)。

Mermaid 围栏作为本地图像来源进入同一异步缓存，缓存键包含完整源码，避免编辑后复用旧图。布局从 Markdown 事件提取完整代码内容，支持列表/引用缩进；不活跃时生成可点击的图块标题并插入画布行，活跃或跨块选中时仍显示原文。画布行和标题点击映射回围栏起点；增量缓存复用前移除画布装饰行再按当前高度插入，因此异步完成和栏宽变化不改变源码映射。

渲染使用锁定的官方 Mermaid 11.17.2 + ZenUML，经本地 Node.js/Puppeteer 运行预打包的 JS；首次 `npm ci --prefix scripts/mermaid` 下载依赖与浏览器，运行时不下载任何资源。组件位置默认使用编译时的项目目录，可通过 `LINKNOTE_MERMAID_DIR` 覆盖。每次渲染使用独立浏览器，页面 CSP 与请求拦截共同禁止外部资源，图表初始化指令不能放宽安全配置；ZenUML 偏好设置使用内存 Storage。正常结束关闭浏览器，25 秒超时后在 Unix 上杀掉本次渲染的独立进程组；临时源码和图像由 TempDir 清理。正文预览输出限 1600 × 2400 像素，图表画布最高 80 行；普通图片保持原有限额。图表不会修改笔记或启动常驻服务。

冲突时不再只有“另存副本”：差异视图用 similar 按行比较磁盘版本与本地版本，用户可以改用磁盘版本（本地文本留在撤销历史）或明确选择覆盖。有未解决冲突的笔记在切换时保存在恢复草稿中，不阻止打开其他笔记。草稿只记录原文件的长度与 FNV-1a 指纹，旧版草稿中的完整原文件仍能读取。

暂不含反向链接列表、图谱、同步、富表格操作、数学公式排版。后续优先：增量 Markdown 解析（4 MiB 文件输入延迟的主要来源）、词边界折行、反向链接、其他平台实测。保存检查与原子替换之间不能阻止不合作的外部程序写入；并发笔记同步应由独立协议解决。

验证命令见 README「开发与验证」，操作入口见 [usage.md](usage.md)。

## 统一设置入口

右上角可点击入口及 Ctrl+, 打开同一个模态设置面板，分「外观」「图表与图片」「快捷键」。设置面板拦截键盘、粘贴和鼠标，保持原笔记光标/选区；设置持久化成功后再应用到界面，失败留在面板提示。打开面板会重新读取 settings.json 与 keys.json。单项快捷键录入保留其余配置，拒绝绑定冲突，允许恢复该动作的默认键。

整体深浅主题在绘制阶段选择调色板，并把布局中的语义颜色映射成可读的浅色配色；不修改源码或排版缓存。图像配置变化会使旧结果失效、清空缓存并重新渲染，仍保留正在运行的任务计数，避免快速切主题突破两任务并发限制。侧栏设置不触发图像重新生成。

Mermaid 默认跟随应用主题，图块 frontmatter 可覆盖主题/字号；渲染器读取最终生效的主题后设置画布背景，支持跟随、深色、浅色和透明。透明 PNG 由终端图片层与当前界面底色合成。全局偏好保存在应用配置目录，侧栏宽度及按笔记的网络许可复用原 session 存储。

## 全屏图片查看器

图片预览右侧预留四列提供 🔍 按钮，避免原生图像协议覆盖按钮，F10（可重绑 `view_image`）通过源码位置识别普通图片、引用式图片和 Mermaid 围栏；同一行多图分别定位。查看器是独立的只读模态状态，绘制时不重建正文布局，不移动笔记光标或选区，关闭后恢复原画面；键盘、粘贴、拖动均先路由到查看器。自动保存与外部修改检测继续运行。

每个查看器只有一个后台工作线程持有原图或 SVG。正文保留原有缩略缓存，查看器按需重新解码普通图片；网络许可由 Images 在启动任务前统一检查。缩放相对适应窗口，范围 0.25–16 倍；平移按像素计算并限制在图像边界，窗口变化保留缩放和中心。渲染任务合并积压请求，并通过代次号丢弃旧视口结果。屏幕只编码可见图像，限制边长 4096、总像素 800 万，避免放大倍率变成巨大位图内存。

Mermaid 查看时只解析一次源码并保留官方引擎产生的 SVG；随后由隔离的本地 Puppeteer 按目标比例/偏移截取视口，沿用离线资源策略、25 秒超时与进程组清理。每次工作结束关闭浏览器，关闭查看器会取消正在执行的渲染，无常驻服务。普通图片下载沿用 8 秒超时；关闭查看器后未完成的下载不再回写 UI。

系统打开仅由 O 或按钮触发：本地图片使用原文件；网络图片使用解码后的本地 PNG；Mermaid 使用嵌入 SVG 的本地 HTML，CSP 阻止脚本及外部资源，保留浏览器矢量缩放。已交给系统应用的临时文件由 App 持有直到退出，避免关掉模态窗口就删掉文件；未打开的临时文件随查看器清理。
